# 开发者 AI 周刊 (dev-ai-weekly)

从公开源抓取、筛选并生成一期中文「开发者 AI 周刊」。定位：AI 工具 / 模型 / Agent **如何落地到真实开发**。不设「版本发布」「前端专栏」板块。**AI 开发者主题占比 > 50%**：按快讯 + 技术文章 + 工具推荐的条目总数计，AI 开发者主题（AI 编程、Agent、模型、AI SDK、MCP 等落地开发）必须超过一半；其余可收两类：非 AI 的优质开发者内容（前端、工程、架构、开源工具等），以及与 AI 相关但非开发者向的内容（AI 产品、行业趋势、政策、社会影响等），同样遵守卡片与落地建议规则，不单开栏目。编号自 #62 起延续旧刊，不重置。

**完成整期的标准：** `src/content/blog/weekly-N.md` 已写入；标题为 `开发者 AI 周刊 #N：…`；含卷首（≥600 字）、必填板块与每条卡片的「落地建议」；链接均为最终 URL；用户已确认素材清单。

## 不做什么（选题硬过滤）

- 不追融资 / 估值八卦
- 安全对齐、政策类只写对读者有实际影响的短条或卡片，不写长篇空论
- 不报无关具身机器人 / 硬件秀（除非有可调用的 API / SDK）
- 不与日更媒体拼「全量快讯」：宁少勿滥，强调筛选与工程点评

## 工作流程（4 阶段）

抓取 → 合并用户链接 → 筛选确认 → 生成文件。任一步未达完成标准不得跳入下一步。

## 阶段一：抓取素材

**完成标准：** 每个可达源都有条目列表（或已标明跳过原因）；素材带标题、最终向链接、一句话描述、粗分类。

并行抓取（`web_fetch` / 等价工具，强制刷新）。某源失败则告知用户并继续。

### AI 主源（每期必查）

1. **TLDR AI** — `https://tldr.tech/ai` 或 `https://ai.tldr.tech/`
2. **Latent Space AINews** — `https://www.latent.space/s/ainews`
3. **AI 开发者日报** — `https://ainews.liduos.com/`
4. **官方 changelog（按需打开本周有更新的）：** OpenAI / Anthropic / Google AI、Vercel AI SDK、Cursor、Claude Code、MCP 相关发布说明
5. **阮一峰科技爱好者周刊** 当周卷首与 AI 相关条目 — `https://www.ruanyifeng.com/blog/weekly/`

### 可选补充（仅收录与 AI 挂钩的条目）

- Hacker News：本周 AI 编程 / Agent / SDK 热帖
- GitHub Trending：AI 开发工具、Agent 框架、MCP server
- Frontend Focus / JavaScript Weekly / Node Weekly / React Status：**不要**扫整刊；仅当条目明确与 AI 挂钩（浏览器内模型、AI SDK 前端用法、编程助手进前端流程等）时才捞入，并归入技术文章 / 工具 / 快讯，不单开前端栏

每条提取：标题 + 链接 + 短描述（若有）+ 分类（快讯 / 技术文章 / 工具）。

## 阶段四：生成周刊

### 4.1 期号与日期

**完成标准：** N = `src/content/blog/` 中最大 `weekly-N` + 1；`pubDate` 为当周周一（`YYYY-MM-DD`；若今天周一则用今天，否则用即将到来的周一）。

### 4.2 Frontmatter

```yaml
---
title: "开发者 AI 周刊 #N：关键词1、关键词2与关键词3"
description: "关键词1，关键词2，关键词3"
pubDate: YYYY-MM-DD
heroImage: "../../assets/blog/weekly-N/hero.jpg"  # 可选；路径相对本 md
---
```

- 冒号后至少 **1 个可搜索英文产品/版本名**（如 `AI SDK 6`、`Claude Code`、`TypeScript 7`），优先来自工具推荐或快讯
- `description` 与 `title` 共享关键词
- `heroImage` 可选：本期封面，对应卷首命题；文件放 `src/assets/blog/weekly-N/`（Astro `image()` 校验），见 §4.10
- #1–#61 历史标题勿改

### 4.3 板块顺序（生成时严格按此）

0. **卷首**（必填）— 见 4.3.1，≥ 600 字
1. **本周快讯**（可选）— 独立要闻，非下文总结；建议 10–14 条（可含模型 / SDK 发布一句话）
2. **技术文章**（必填）— AI 落地开发为主，建议 6–10（可复现 / 有机制或数字；可含 1 篇机制科普或观点）
3. **工具推荐**（必填）— AI 编程工具、Agent、MCP、SDK 等，建议 8–12，允许小而可试用的项目（重要版本发布并入本栏或快讯，不单开「版本发布」）

**已取消的板块：** 版本发布、前端专栏、本周我验证了。模型/工具发版写进工具推荐或本周快讯；与 AI 挂钩的前端内容并入技术文章或工具推荐。

### 4.3.1 卷首（必填）

每期开头一篇卷首，**不少于 600 字**（中文字符计，不含链接 URL），放在本周快讯之前，不加 `##` 标题以外的花哨栏名（用 `## 卷首` 或直接以卷首命题为 `##` 标题均可）。

- **功能**：定调，不是复述本期清单；讲本期最值得想的一件事。
- **题材**：工程方法论（阶段、eval、成本、工作流）、机制科普、趋势判断三选一；与 AI 落地开发直接相关。
- **结构**：场景或事件 → 机制或论点 → 1–2 个例子或数字 → 保留意见（Yes, but）→ 一句落地判断。
- **语气**：口语、具体、有立场；不写空泛感想、不做本期目录。
- **标题**：卷首命题优先作为期号副标题关键词（仍需含 1 个可搜索英文产品名）。
- 可与后文某条呼应，但不强制。
- **配图**：卷首内可插 1–2 张机制/对比图（见 §4.10）；封面用 `heroImage`。

### 4.4 本周快讯格式

关键词用中文：

```markdown
## 本周快讯

- [关键词](链接) 一句话描述。
```

### 4.5 卡片格式（技术文章 / 工具推荐）

信息层次参考 The Batch 的 brief（压缩成中文短卡片，不照搬六段长文）：

| The Batch 层次 | 咱们怎么用 |
|----------------|------------|
| What’s new | 第一段 1–2 句：发生了什么 |
| How it works + 关键数字 | 中间段：机制 **或** 可核对数字（价格、榜单、限制） |
| Why it matters / We’re thinking | 末段固定 **落地建议：** 或 **谁该关心：** |
| Behind the news | 快讯里一句竞品/政策上下文即可，不必独立长段 |
| Undisclosed / Yes, but | 写进中间段或落地建议的条件句，避免空泛推荐 |

- 标题 `### [中文标题](链接)`：英文原题须译成简洁中文
- **2–3 个短段落**（版式与卷首相同：正文流，无卡片边框）；段间空行；配图见 §4.10；代码块在全部段落后
- **最后一段必须是落地句**，固定前缀二选一：
  - `落地建议：…`（默认）
  - `谁该关心：…`（受众边界比行动建议更重要时）

| 段落 | 内容 | 字数 |
|------|------|------|
| 第一段 | 来源 + 这是什么（What’s new） | ≤ 80 |
| 第二段 | 机制 **或** 可核对数字（价格、上下文、第三方评测、门禁/数据保留）；研究向先用一句 Key insight | ≤ 100 |
| 第三段 | **落地建议：…** 或 **谁该关心：…**，点明适用阶段或约束条件 | ≤ 60 |

```markdown
### [中文标题](链接)

![可选配图说明](../../assets/blog/weekly-N/slug.png)

第一段：来源与主题。

第二段：机制或可核对数字（勿只写「XX 发布了」）。

落地建议：具体到「谁、在什么场景/阶段、可先试哪一步、有何约束」。
```

**示例：**

```markdown
### [Vercel AI SDK 6：统一工具调用与流式 UI 协议](https://example.com)

Vercel 发布 AI SDK 6，把多模型工具调用与流式 UI 事件收成同一套客户端协议。

核心变化是 tool call 与 UI message stream 对齐，React / Vue 示例可直接订阅部分更新，减少手写 SSE 胶水。

落地建议：已在用 AI SDK 的 Next 应用先升 6.x，用官方 `useChat` 示例在 staging 验证工具调用流，再迁自定义 transport。
```

### 4.6 卡片写作纪律（The Batch 压缩版）

1. **工具与发版向**：禁止只有「XX 发布了」；中间段至少包含机制 **或** 可核对数字之一，再写落地建议。避免「标题翻译 + 空泛推荐」。
2. **落地建议对齐读者阶段**：早期原型 vs 成熟线上；末段点明阶段或约束（门禁、数据保留、ZDR、适用场景）。
3. **成本优先写「每任务 / 每小时」**，优于只写「每百万 token」。
4. **门禁与数据政策单独点一句**（谁能用、数据留多久）。
5. **研究向卡片**：先用一句话点出 Key insight（要解决的工程问题），再写方法要点与落地建议（接到自己的 agent harness）。
6. **快讯栏**：留给同日对比、政策、短讯；深度机制放进技术文章 / 工具推荐。
7. 不模仿长卷首信、不拉长到 20 分钟阅读、不单独「版本发布」栏；可执行落地句，避免文艺收尾。

可选参考源：保留 [The Batch](https://www.deeplearning.ai/the-batch/) 作**结构与写法参考**（非每条必转载）；素材仍优先 TLDR AI / 厂商 changelog / 论文。

### 4.7 写作硬规则

- 中文；单段 ≤ 150 字、最多 2 句；禁止分号串 3 个以上信息点
- `**加粗**` 每段最多 2 处
- 避免空洞赞美；工具写清解决什么问题；版本写清变更与影响
- 每条卡片都有落地句；缺落地句 = 未完成
- 写入前用 `.agents/scripts/resolve-url.sh`（或等价 curl 跟随重定向）把链接收成**最终 URL**

### 4.8 板块内排序

影响面广 → 技术深度 → 实用价值 → 话题热度。

### 4.9 输出

写入 `src/content/blog/weekly-{N}.md`。**完成标准：** 文件存在；卷首 ≥ 600 字；必填板块齐全；每张内容卡片含落地句；链接已解析；本期配图已按 §4.10 落盘（无图可过，但不外链）。

### 4.10 配图规则

学阮刊视觉密度，**不新开「图片」栏目**。策略：每期 hero + 卷首 1–2 图 + 文章/工具约 ⅓–½ 配图；快讯不配图。

| 位置 | 要不要图 | 写法 |
|------|----------|------|
| 封面 hero | 每期 1 张（强烈建议） | frontmatter `heroImage` → 文件在 `src/assets/blog/weekly-N/hero.jpg`（或 png/webp），路径相对 md，如 `../../assets/blog/weekly-N/hero.jpg` |
| 卷首正文 | 1–2 张机制/对比图 | 普通 Markdown 图，插在相关段落下方：`![说明](../../assets/blog/weekly-N/intro-1.png)` |
| 技术文章 / 工具推荐 | 约 ⅓–½ 条配图 | **紧跟 `###` 标题下一行**单独放图，再跟 2–3 个正文段（与卷首同为正文流，插图统一圆角） |
| 本周快讯 | **不配图** | 保持纯文字列表 |

**条目 Markdown 结构（写作仍叫「卡片」，版式无框）：**

```markdown
### [标题](链接)

![项目截图或架构图](../../assets/blog/weekly-N/tool-foo.png)

第一段 …

第二段 …

落地建议：…
```

- 图必须独占一行（渲染为「仅含 `<img>` 的 `<p>`」）；不要把图和文字写在同一段。
- 有图时正文仍是 2–3 段；无图时结构与旧刊完全相同。
- 代码块仍放在全部正文段之后。

**图源与版权：**

1. 优先官方博客 / 文档 / GitHub README / 产品页截图或原文配图；架构图、评测图亦可。
2. **下载进仓库，禁止外链热图**：正文图与 hero 一律放 `src/assets/blog/weekly-N/`（与 hero 同目录）；Markdown 用相对路径 `../../assets/blog/weekly-N/...`。下载原图入库即可，构建时由 Astro（sharp）生成优化版本（如 webp），无需另跑压缩脚本。不要再放到 `public/blog/`。
3. 文件名用英文短横线（如 `decisions-api.png`）；`alt` 写清内容，勿堆 SEO 关键词。
4. 版权或来源不清 → **宁可不配**；不盗用无关美图、不配与条目无关的装饰图。
5. 不新开「图片」「封面秀」等栏目。

## 选题过滤器与体量

综合 The Batch（把一条写硬）与阮一峰周刊（一期够厚、可跳读）：

- **「多」= 条目多，卡片仍短**：靠增加可点开的条目变厚（AI 开发者主题 > 50%），不加长散文，不加通识栏目。
- **快讯可以短而多**：一句话，可报发版、同周对比；文章 / 工具卡必须有机制或可核对数字 + 落地建议。
- **加厚优先顺序**：先加工具和快讯；技术文章守住可复现工程文的门槛。
- **工具栏当弹性仓**：头部厂商之外，收能接进工作流的小工具、MCP server、本地模型周边；用户提供的链接优先。
- **拒绝两端**：不开图片、言论、往年回顾等栏目，其他条目不得过半；也拒绝 Batch 式整期只有约 4 条深度的过薄形态。
- 模型名刷屏只允许留在快讯；进文章 / 工具就必须写机制、数字或约束。

## 内容筛选偏好

优先：

1. 影响开发者工作流的模型 / SDK / Agent / MCP 发布与实践
2. 可复现的工程文（评测、架构、接入、成本、可观测性）
3. 解决真实痛点的 AI 开发工具
4. **与 AI 挂钩的前端**（浏览器内模型、前端 AI SDK、编程助手进前端流程）——写入技术文章或工具，不单开栏

避免：广告软文、过小众且无复现路径、多源重复条目、纯融资估值八卦；其他条目若使 AI 开发者主题占比 ≤ 50%，优先删其他条目。
