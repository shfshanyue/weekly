# 开发者 AI 周刊 (dev-ai-weekly)

从公开源抓取、筛选并生成一期中文「开发者 AI 周刊」。定位：AI 工具 / 模型 / Agent **如何落地到真实开发**；固定保留「前端专栏」（优先 AI × 前端）。编号自 #62 起延续旧刊，不重置。

**完成整期的标准：** `src/content/blog/weekly-N.md` 已写入；标题为 `开发者 AI 周刊 #N：…`；含必填板块与每条卡片的「落地建议」；链接均为最终 URL；用户已确认素材清单。

## 不做什么（选题硬过滤）

- 不追融资 / 估值八卦
- 不写安全对齐、政策长文（除非直接改变开发者可用的 API / 产品行为）
- 不报无关具身机器人 / 硬件秀（除非有可调用的 API / SDK）
- 不与日更媒体拼「全量快讯」：宁少勿滥，强调筛选与工程点评

## 工作流程（4 阶段）

抓取 → 合并用户链接 → 筛选确认 → 生成文件。任一步未达完成标准不得跳入下一步。

## 阶段一：抓取素材

并行抓取（`web_fetch` / 等价工具，强制刷新）。某源失败则告知用户并继续。

## 阶段四：生成周刊

### 4.1 期号与日期

**完成标准：** N = `src/content/blog/` 中最大 `weekly-N` + 1；`pubDate` 为当周周一（`YYYY-MM-DD`；若今天周一则用今天，否则用即将到来的周一）。

### 4.2 Frontmatter

```yaml
---
title: "开发者 AI 周刊 #N：关键词1、关键词2与关键词3"
description: "关键词1，关键词2，关键词3"
pubDate: YYYY-MM-DD
---
```

- 冒号后至少 **1 个可搜索英文产品/版本名**（如 `AI SDK 6`、`Claude Code`、`TypeScript 7`），优先来自版本发布或快讯
- `description` 与 `title` 共享关键词
- #1–#61 历史标题勿改

### 4.3 板块顺序（生成时严格按此）

1. **本周快讯**（可选）— 独立要闻，非下文总结；建议 8–10 条
2. **技术文章**（必填）— AI 落地开发为主，建议 5–8
3. **工具推荐**（必填）— AI 编程工具、Agent、MCP、SDK 等，建议 5–8
4. **版本发布**（必填）— 模型 / AI SDK / 开发工具发布，建议 4–6
5. **前端专栏**（必填）— **3–5 条**；优先浏览器内 AI、AI SDK 前端用法、Copilot/Agent 与前端工作流、Web 平台与本地模型；纯 Vite/CSS 仅当影响面极大时选入
6. **本周我验证了**（可选）— 至多 1 条：作者或 Agent 真实跑过的工具/SDK/MCP，写清环境、结论、坑

### 4.4 本周快讯格式

关键词用中文：

```markdown
## 本周快讯

- [关键词](链接) 一句话描述。
```

### 4.5 卡片格式（技术文章 / 工具 / 版本发布 / 前端专栏）

- 标题 `### [中文标题](链接)`：英文原题须译成简洁中文
- **2–3 个短段落**（站点把 h3 后连续 1–3 个 `<p>` 收成卡片）；段间空行；代码块在全部段落后
- **最后一段必须是落地句**，固定前缀二选一：
  - `落地建议：…`（默认）
  - `谁该关心：…`（受众边界比行动建议更重要时）

| 段落 | 内容 | 字数 |
|------|------|------|
| 第一段 | 来源 + 这是什么 | ≤ 80 |
| 第二段 | 核心亮点 / 关键数字 / 技术细节 | ≤ 100 |
| 第三段 | **落地建议：…** 或 **谁该关心：…**（必填） | ≤ 60 |

```markdown
### [中文标题](链接)

第一段：来源与主题。

第二段：核心亮点或关键数字。

落地建议：具体到「谁、在什么场景、可先试哪一步」。
```

**示例：**

```markdown
### [Vercel AI SDK 6：统一工具调用与流式 UI 协议](https://example.com)

Vercel 发布 AI SDK 6，把多模型工具调用与流式 UI 事件收成同一套客户端协议。

核心变化是 tool call 与 UI message stream 对齐，React / Vue 示例可直接订阅部分更新，减少手写 SSE 胶水。

落地建议：已在用 AI SDK 的 Next 应用先升 6.x，用官方 `useChat` 示例验证工具调用流，再迁自定义 transport。
```

### 4.6 写作硬规则

- 中文；单段 ≤ 150 字、最多 2 句；禁止分号串 3 个以上信息点
- `**加粗**` 每段最多 2 处
- 避免空洞赞美；工具写清解决什么问题；版本写清变更与影响
- 每条卡片都有落地句；缺落地句 = 未完成
- 写入前用 `.agents/scripts/resolve-url.sh`（或等价 curl 跟随重定向）把链接收成**最终 URL**

### 4.7 板块内排序

影响面广 → 技术深度 → 实用价值 → 话题热度。

### 4.8 输出

写入 `src/content/blog/weekly-{N}.md`。**完成标准：** 文件存在；必填板块齐全；每张内容卡片含落地句；链接已解析。

## 内容筛选偏好

优先：

1. 影响开发者工作流的模型 / SDK / Agent / MCP 发布与实践
2. 可复现的工程文（评测、架构、接入、成本、可观测性）
3. 解决真实痛点的 AI 开发工具
4. **AI × 前端**（浏览器内模型、前端 AI SDK、编程助手进前端流程）
5. 大影响面的运行时 / 语言版本（仅当开发者本周必须知道）

避免：广告软文、过小众且无复现路径、多源重复条目、纯产品/AIGC 八卦、与开发无关的行业新闻。

---

## 注意

- 源不可达：跳过并告知，不阻塞其他源
- 去重：同一链接或同一项目只留一次
- 用户只说「写周刊」：从阶段一开始
- 用户甩链接「用这些写」：可从阶段二/三开始
