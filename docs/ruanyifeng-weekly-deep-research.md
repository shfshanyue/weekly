## 2. 出版节奏与受众

### 2.1 节奏

- 自称：**每周五**发布科技分享；归档自「每周分享」时代延续至今，**期号已过 414**。
- 近窗：#409（8/21）→ #410（8/28）→ #411（9/4）→ #412（9/11）→ #413（9/18）→（假期）→ #414（10/8），常态周更，假期可休刊。
- 分发：**博客为主** + GitHub 开源 Markdown + RSS/邮件/Substack；读者可在博客留言（#414 可见数十条讨论）。

### 2.2 受众（从定位与选题反推）

- 自我表述：「记录每周值得分享的**科技内容**」——不是「仅 AI」，也不是「仅前端」。
- 实际读者画像：**广义科技爱好者 / 程序员**，愿意扫：工程工具、行业奇闻、地图/硬件/数学、职业思考、AI 科普。
- 与咱们差异：咱们是 **「开发者 × AI 落地」垂直刊**；阮刊是 **科技通识超市**，AI 是强主线之一，但不是唯一货架。

### 2.3 他们卖的差异化

| 资产 | 表现 |
|------|------|
| **个人品牌卷首** | 每期用 1–2（有时更多）篇短文定调，标题即期名 |
| **栏目超市** | 封面 / 主题 / 科技动态 / 文章 / 工具 / 资源 / 图片 / 文摘 / 言论 / 往年回顾 |
| **开源共创** | 工具/资源大量标注 GitHub issue 投稿 |
| **宁多勿少** | 工具栏常 **10–18** 条；全期链接条目常 **30+** |
| **可读短评** | 多数条目 1–3 句点评 + 配图，不是六段 brief |

对咱们的启示：中文读者已经习惯「**一期很厚、可跳读**」的周刊形态；若咱们压得过少，会显得「不像周刊」。但若照搬超市广度，会稀释「开发者 AI」品牌。

## 3. 一期解剖（Issue anatomy）

近 6 期稳定骨架（#414 略有变体）：

```
1. 期首说明（开源 / 投稿 / 谁在招人 / 合作邮箱）
2. 封面图（一张图 + 一句说明）
3. 卷首主题文 ×1–2（偶发再附 1–2 则短主题，或拆成多则「类动态」短文）
4. 科技动态（2–4 则；常含「一句话新闻」子列表）——#414 用多则短主题替代，未开此栏
5. 文章（稳定约 6 则）
6. 工具（约 10–18 则，投稿密集）
7. 资源（约 3–5 则）
8. 图片（1–2 则配图故事）
9. 文摘（0–2 则，摘录长文片段）——#414 未开
10. 言论（约 4–5 则金句）
11. 往年回顾（固定链回大约 50/100/150/200 期前的同号主题）
```

### 3.1 卷首 / 主题文

- **功能**：不是复述新闻清单，而是 **观点或科普定调**；期号副标题 = 主主题名。
- **近 6 期主题类型**：

| 期号 | 主主题 | 类型 | AI 相关？ |
|------|--------|------|-----------|
| 414 | Jev 决策模型有什么用 | 产品机制科普 + 用例 + 引用 Simon 保留意见 | 强 |
| 413 | 再见了，React Native | 工程趋势观点（Shopify 回原生，AI 当「翻译器」） | 强（借 AI 论证） |
| 412 | 禁止 issue，只用 PR | 开源协作方法论（Laravel；AI 降低 PR 门槛） | 中强 |
| 411 | OpenClaw 2.0 是一个缩影 | AI 产品节奏 / Vibe Coding / 安全隔离建议 | 强 |
| 410 | 你需要知道的 AI 三种机制 | AI 小知识系列（参数 / 推理 / 联网） | 强 |
| 409 | 程序员的职业未来 | 职业结构化预测（coding agent、工业化） | 强 |

- 副主题常见：第二篇短文（如 #409「大模型优化技巧」、#411「没人为你的堆栈辩护」、#413「世界地图投影」）——**科技通识或职业旁支**，不保证 AI。
- 长度：主主题大约 **650–1800 汉字**量级（Markdown 计）；可独立成文，口语化、举例、配多图。

### 3.2 列表栏目条数（近 6 期实测）

| 期号 | 科技动态 | 文章 | 工具 | 资源 | 图片 | 文摘 | 言论 | 主题文块数 |
|------|----------|------|------|------|------|------|------|------------|
| 414 | （无，改用 4 则短主题） | **6** | **18** | 4 | 2 | — | 5 | 4 |
| 413 | 2（含一句话新闻） | **6** | **10** | 4 | 2 | 1 | 5 | 2 |
| 412 | 3 | **6** | **10** | 3 | 1 | 1 | 5 | 2 |
| 411 | 4 | **6** | **10** | 4 | 2 | 1 | 4 | 2 |
| 410 | 3 | **6** | **10** | 3 | 1 | 1 | 5 | 2 |
| 409 | 3 | **6** | **10** | 5 | 1 | 2 | 4 | 2 |

规律摘要：

1. **文章栏几乎锁死 6 条**——像固定货架格。  
2. **工具栏下限约 10，#414 冲到 18**——「多」主要堆在工具与投稿。  
3. **科技动态偏猎奇/硬件/社会**，不是厂商发版墙。  
4. **言论 + 往年回顾**是品牌仪式感，贡献阅读黏性，不贡献「工程可执行步骤」。

### 3.3 全期体量（阅读感）

| 指标 | 阮刊近 6 期 | 对照：咱们 `weekly-61.md` | 对照：The Batch |
|------|-------------|---------------------------|-----------------|
| Markdown 体量 | 约 **9.7k–12.4k 字符** | 约 8.5k 字符（仍含旧「版本发布」栏） | 单期标注 **18–22 min** 英文长 brief |
| 链接型条目 | 常 **~30–45+**（含动态/文章/工具/资源/言论等） | skill 目标约 **15**；#61 约 18 张 `###` 卡 | 约 **4** 条长 News |
| 阅读方式 | **跳读超市**：先看卷首，再扫工具/文章 | 卡片连续读 | 精读每条 |

结论：阮刊的「多」是 **条目数量多、单条短**；Batch 的「深」是 **条目少、单条长**。咱们当前 skill 更靠近 Batch 的少，但用户期望 **写得更多**——应学阮刊的 **货架容量**，保留 Batch 的 **卡片信息层次**。

## 4. 单条写法

### 4.1 文章 / 工具 / 资源的标准颗粒

典型形态（工具例，#414）：

```text
N、[项目名](url)
（可选配图）
1–3 句：这是什么 + 一两个卖点；（常附）(@contributor 投稿)
```

- **没有** What’s new / How it works / Performance / Why it matters 分层。  
- **没有** 固定「落地建议：」前缀。  
- 点评可以很主观（「推荐阅读」「这件事的结果不是 A 就是 B」），也可以极短到半句。  
- 英文源常标「（英文）」；中文源偶发。

### 4.2 科技动态

- 1–2 则稍长（3–8 句）+ 可选「一句话新闻」子列表（（1）（2）（3）…）。  
- 选题：隐藏摄像头、地图投影、日食拍照 Bug、电动飞机、Cybercab……**通识好奇心**优先于「本周必须装进工作流」。

### 4.3 卷首文写法（和 Batch 卷首的差别）

| | 阮一峰卷首 | Andrew / The Batch 卷首 |
|--|------------|-------------------------|
| 目标 | 讲清楚一个观点或科普块 | 定调工程方法论 / 行业叙事 |
| 结构 | 故事 → 机制/论点 → 例子 → 收束（偶引第三方异议） | 教学口吻长文，常系列化 |
| 与后文关系 | 后文栏目相对独立，不要求呼应 | News 与信可同主题共振 |
| 可执行性 | 偶有（如 #411「别在工作电脑跑 OpenClaw」） | 常落到阶段/eval/工作流 |

#414 对 Jev：先讲「返回浮点概率」→ 两个浏览器插件用例 → 再引 Simon Willison「黑箱倒退」担忧——**热情介绍 + 保留意见**，接近 Batch 的 Yes, but，但粒度仍是散文而非规格表。

## 5. 篇幅、语气与信息密度

### 5.1 篇幅策略

- **卷首长、条目短**：把深度预算花在主题文；列表靠数量取胜。  
- 单条工具常 **40–120 字**点评；文章略长一点。  
- 全期字符与咱们单期接近，但 **条目数约为咱们 skill 目标的 2 倍以上**。

### 5.2 语气

- 口语、第二人称「大家」「你就会明白」。  
- 敢下判断（「三个理由都是场面话，真正的理由只有一个：省钱」）。  
- 少堆 Benchmark；数字出现时多为叙事服务（16000 个 PR、1300 万行 Lean 证明等），**不是**系统化的 $/task 表。

### 5.3 信息密度偏好（实测）

优先出现：

1. **好懂的机制隐喻**（决策模型=是非题/选择题/评分；AI 三种机制=参数/推理/联网）  
2. **一个能转述的故事**（Shopify 六年前后矛盾；Laravel 禁 issue）  
3. **可点开的链接 + 一张图**  
4. **投稿署名**（社区感）

较少出现：

- 独立评测榜、价格矩阵、Undisclosed 规格条、门禁/ZDR 清单  

→ 这正是咱们已从 Batch 偷来的层次；**阮刊不替代 Batch 的卡片纪律**。

## 6. 选题与体量（重点：条数、栏目配比、AI 占比、过滤器哲学）

### 6.1 选题广度：科技通识超市

货架同时装：

- **AI / 模型 / Agent / 职业**（卷首高频）  
- **语言与前端/后端工程**（Deno/Node、JS 怪异、HTML 模板）  
- **开源协作与工具链**（issue/PR、Git、终端工具）  
- **硬件 / 出行 / 地图 / 数学 / 艺术**（科技动态、图片、资源）  
- **金句与人文**（言论、文摘）

哲学可以概括成：**宁多勿少 + 跳读友好 + 好奇心及格即可收录**。  
不是「每周只给开发者 4 条必须精读的 brief」。

### 6.2 AI 占比（近 6 期，定性 + 半定量）

| 层 | AI 浓度 | 说明 |
|----|---------|------|
| 卷首主主题 | **极高（6/6）** | 全部可直接或借 AI 立论 |
| 副主题 | 中等 | 约一半强 AI，一半通识 |
| 文章栏（6 条） | **约 1–3 条/期** | 其余为通用工程/轶事 |
| 工具栏（10–18） | **少数** | 大量通用 CLI/桌面/自托管；AI 工具混入但不主导 |
| 科技动态 | **偏低** | 猎奇与硬件为主 |

因此：对外品牌常被感知为「最近老谈 AI」，但**结构上仍是综合科技周刊**；列表栏并没有变成 AI-only。

### 6.3 「宁多勿少」如何落地

1. **固定格**：文章 ≈6，言论 ≈4–5，往年回顾 4 链。  
2. **弹性仓**：工具 10→18，靠投稿与编辑扫货加厚。  
3. **低门槛收录**：只要「值得知道/好玩/有用」之一成立即可；不要求每条可进生产工作流。  
4. **用栏目隔离风险**：奇闻进「科技动态/图片」，硬核进「文章/工具」，观点进卷首——读者可跳读。

### 6.4 与咱们现状的体量对照

| 维度 | 阮刊 | The Batch | 咱们 skill 现状（v2.3） |
|------|------|-----------|------------------------|
| 主栏条目目标 | 文章6+工具10–18+… | News ≈4 | 快讯8–10 + 文章5–8 + 工具5–8 ≈ **15 左右** |
| 单条深度 | 短评 | 六段长 brief | 三段中文卡片 + 落地建议 |
| 过滤器 | 宽（科技爱好） | 窄（AI practice） | 窄（开发者 AI 落地）+ 已写入 Batch 卡片纪律 |
| 「多」的来源 | **加条目** | **加段落** | 当前偏 Batch；用户希望更接近阮刊的「多」 |

### 6.5 可与 Batch §7.3 对照的「选题/体量」建议（供后续决策）

> **待与 Batch 综合后再改 skill；本节只提案。**

Batch §7.3 精神：每周粗配比 **2 工具或发版 + 1–2 文章/方法**，避免模型名刷屏，拒绝无工程句柄八卦。  

阮刊精神：****货架要厚**，用栏目分流，允许通识与短链存在。**

综合提案（供你拍板）：

1. **不要照搬 Batch 的「整期大约 4 条深度」**——中文周刊读者预期更接近阮刊的厚度。  
2. **不要照搬阮刊的通识超市**——奇闻/地图/金句/往年回顾不是咱们护城河。  
3. **建议体量（草案）**：在保持三段卡片 + 落地建议的前提下，把 skill「约 15 条」上调到大约：  
   - 本周快讯：**10–14**（一句话，可含发版）  
   - 技术文章：**6–10**  
   - 工具推荐：**8–12**  
   - 合计主链路由约 **24–36** 条量级，仍低于阮刊全栏目总和，但明显高于 Batch，也高于当前 15。  
4. **加厚优先顺序**：先加工具与快讯（阮刊弹性仓），文章保持「可复现工程文」质量门槛（Batch 纪律）。  
5. **过滤器**：继续拒绝融资八卦/无 API 硬件秀；但允许更多「边缘但可试用的 AI 开发小工具」进工具栏——学习阮刊投稿漏斗，而不是只收头部厂商。

## 7. 可偷给「开发者 AI 周刊」的做法

约束回顾：咱们格式是 **本周快讯（可选）→ 技术文章 → 工具推荐**；卡片末段 **落地建议 / 谁该关心**；已吸收 Batch §7/§9（除选题过滤器）；**无版本发布栏、无前端专栏**。

### 7.1 直接可偷

| 阮刊做法 | 咱们怎么用 |
|----------|------------|
| **宁多勿少的工具仓** | 工具栏目标上调；多收可 clone 的小工具/MCP/本地模型周边 |
| **文章栏固定容量感** | 维持「大约一排」的稳定格数（可从 5–8 提到 6–10），读者形成预期 |
| **卷首定调但不串场** | 不强制每期主编长文；但选题时可有一条「观点/机制科普」气质的技术文章（类 #410 三种机制、#414 Jev） |
| **短评 + 外链** | 快讯栏保持一句话；深度留给卡片 |
| **投稿/共创** | 中长期可考虑公开「欢迎提链接」；短期在生成流程继续「合并用户链接」 |
| **热情介绍 + 一句保留** | 与 Batch Yes, but 合流：落地建议里写约束（#411 隔离运行即范例） |
| **跳读友好的栏目边界** | 快讯=扫，文章/工具=读；不要把奇闻塞进技术文章栏 |

### 7.2 对「写得更多」的操作含义

- 「更多」应表现为：**更多可点开的 AI 开发相关条目**，而不是更长散文。  
- 单卡仍遵守 Batch 压缩层次（机制或数字 + 落地建议）；**靠增加卡片数**接近阮刊厚度。  
- 快讯可以更「阮」：短、多、可含同周对比；文章/工具必须更「Batch」：可核对、可落地。

## 8. 明确不要照搬的部分

1. **科技通识超市**：地图投影、日食拍照、有轨电车利润率图——好看，但稀释「开发者 AI」。  
2. **封面图 / 图片 / 文摘 / 言论 / 往年回顾**：仪式感强，维护成本高，且与落地无关。  
3. **「谁在招人」与合作广告位**：商业模式不同。  
4. **工具栏无筛选地堆到 18 条通用 CLI**：咱们若堆非 AI 工具，会回到旧前端周刊形态。  
5. **只有主观短评、没有落地句**：与已写入 skill 的卡片纪律冲突。  
6. **把期号做成「人生/社会长文杂志」**：阮有个人品牌与 400+ 期信任；咱们应用工程筛选建立信任。  
7. **假期随意休刊但不改读者预期**：可休，但要像 #413 一样文首说清；流程上仍建议稳定周更。

## 9. 与 The Batch 对照（含选题过滤器对照表）

### 9.1 三种形态

| | The Batch | 阮一峰周刊 | 开发者 AI 周刊（目标态） |
|--|-----------|------------|-------------------------|
| 隐喻 | **观点信 + 六段 brief** | **栏目超市 + 短评** | **中文落地卡片货架** |
| 权威来源 | Andrew Ng 人设 | 阮一峰人设 | 筛选标准 + 工程点评（无人设信） |
| 条数 | 极少而深 | 极多而薄 | **中多而有层次**（提案） |
| AI 纯度 | 极高 | 卷首高、列表中低 | 应保持高 |
| 成本/评测 | 强（$/task 等） | 弱 | 已按 Batch 纪律加强 |
| 读者动作 | 理解 + 判断 | 发现 + 收藏链接 | **试用 / 接入工作流** |

### 9.2 选题过滤器对照（Batch §7.3 vs 阮刊 vs 综合提案）

| 议题 | Batch §7.3 | 阮刊实际 | 综合提案（待你拍板） |
|------|------------|----------|----------------------|
| 每周深度主条 | 约 4 条 News | 卷首 1–2 + 列表海量 | 文章 6–10 + 工具 8–12 + 快讯 10–14 |
| 工具/发版 | 2 条量级进 News | 工具 10–18，发版不单栏 | 发版进快讯或工具；**工具条数向阮刊靠** |
| 研究/方法 | 每期 ≥1 | 不固定；卷首常当科普 | 文章栏保留方法/评测文，学 Batch Key insight |
| 八卦/融资 | 拒绝 | 偶有产业新闻进文章 | **拒绝**（保持现 skill 硬过滤） |
| 通识猎奇 | 几乎无 | 科技动态主力 | **不进主栏**；除非直接改变开发者可用 API |
| 模型名刷屏 | 避免整期都是 | 不在意 | 快讯可多报，文章/工具要有机制或数字 |
| 「多」的定义 | 段落多 | 条目多 | **条目多 + 卡片仍短** |

### 9.3 一句话对照

- Batch 教咱们：**怎么把一条写硬**。  
- 阮刊教咱们：**一期要够厚、够可跳读**。  
- 咱们应：**Batch 的骨（层次/诚实边界）+ 阮刊的肉（条目容量）**，骨架栏目仍只保留快讯/文章/工具。

## 10. 对 `dev-ai-weekly` 的可选补丁（先不落地）

> **标注：待与 Batch 综合后再改 skill。本轮调研不得修改 `SKILL.md` / `AGENTS.md`。**

### 10.1 选题条数 / 广度（核心补丁草案）

在「阶段三：筛选展示」与「4.3 板块顺序」中，将体量建议从「约 15 条」调整为类似：

```text
本周快讯：10–14（一句话；发版可进）
技术文章：6–10（可复现 / 有机制或数字）
工具推荐：8–12（优先 AI 编程 / Agent / MCP / SDK；允许更多小而可试用项目）
预筛展示总量：约 28–36，再与用户砍到最终稿
```

并写明过滤器原则：

```text
学阮刊「厚」：增加可跳读条目，不增加通识栏目。
学 Batch「硬」：每张文章/工具卡仍要机制或可核对数字 + 落地建议。
拒绝阮刊式猎奇动态进主栏；拒绝 Batch 式整期只有四条长文的过薄形态。
```

### 10.2 可选、非必须

- 抓取源：继续把阮刊当周 **卷首 + AI 相关列表** 作素材源（skill 已列），但转载时改写成咱们卡片，不复制栏目。  
- 允许一期有 **1 篇「机制科普/观点」气质** 的技术文章（对标卷首功能），仍用落地建议收尾。  
- 工具栏鼓励「投稿感」：用户链接优先，小项目只要可跑通工作流即可收录。

### 10.3 明确先不动

- 不恢复版本发布栏、前端专栏、言论/图片/往年回顾。  
- 不删除已写入的 Batch 卡片层次与写作纪律。

## 11. 结论（一句话）

阮一峰周刊的护城河是 **「个人卷首定调 + 开源栏目超市 + 宁多勿少的跳读体量」**；「开发者 AI 周刊」应偷其 **货架厚度与短链发现感**，与 The Batch 的 **可核对 brief 层次** 合并成「**更多的中文落地卡片**」，而不是偷其通识猎奇栏目，也不是回到每期只有四条英文长文的厚度。
