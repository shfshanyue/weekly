# 周刊与视频术语表

适用：周刊正文、周刊视频口播、精读视频口播与画面译文。这里管含义；TTS 的多音字表只管发音，两者分开维护。

## 先查所指，再译

1. 写到歧义词、新参数或新机制时，先看该产品当前官方定义、参数说明与使用示例，确认它控制什么、作用范围及限制；已有译名也要按本次语境核对。
2. 按下表选词。官方定义仍不足以消歧时保留英文，标明哪里不确定，不凭字面补出机制或效果。
3. 写完分别核对正文、口播、画面译文。口播改写后重新对照原文：中文即使顺口，也可能把参数含义、因果或保证范围说错；正文审过不能替代口播审查。所有歧义均已查清或明确保留英文，才算通过。

## 约定译法

| 原词与语境 | 译法 | 含义边界 |
| --- | --- | --- |
| 模型参数 `effort` / `reasoning effort` | 推理强度；首次可写「推理强度（effort）」 | 指模型投入推理 / 计算的强度；具体控制哪些 token、如何影响工具调用等，以该模型官方定义为准。不译「努力程度」，不等同于回答长度，也不保证档位越高答案就一定正确。普通英语 effort 按句意译，不机械套此表。 |
| `thread`：对话及其会话状态 | 会话；产品名可保留英文 | Claude Message Threads 指服务端临时维护对话状态的会话，不是并发线程。保留产品名时可写「Message Threads（服务端会话）」。 |
| `thread`：并发执行单元 | 线程 | 以程序执行语境判断；不要把会话机制写成并发机制。其他语境另查所指，拿不准保留 thread。 |

## 语义与发音分开

- **语义核对**修改正式正文、`lines[].text`、画面 `zh` 等内容，让中文忠实表达原意。
- **TTS 发音检查**在含义正确之后做。`voice.json` 的 `polyphones`、纠音用 `say` 只改变送去合成的读法，保留字幕原文。翻译 / 术语映射不进入多音字表，也不能靠纠音掩盖字幕中的错译。

## 官方定义入口

查阅时以当次使用的产品、模型版本为准，不把某一模型的参数行为推广到所有模型。

- [Claude effort](https://platform.claude.com/docs/en/build-with-claude/effort)：说明 effort 的 token 范围、与 thinking 的关系，以及与回答长度控制的区别。
- [Claude Message Threads](https://platform.claude.com/docs/en/build-with-claude/message-threads)：说明服务端维护对话、后续仅发送新增消息的机制。
