# 视频周刊（B 站）设计

日期：2026-10-19
状态：待确认

## 意图

每期《开发者 AI 周刊》同时出一支 B 站视频，大约 8 分钟，发在 B 站账号「程序员山月」。视频不是把周刊念一遍：卷首一定讲，其余内容由 Agent 挑适合用画面讲的条目。旁白用山月的 AI 克隆声音。

山月不参与中间环节，只看最终成片并提修改意见。最重要的要求是**每周稳定产出**：做法要能每周照着重复，山月每期花的时间不超过周刊维护预算（每周 1–2 小时）里的一小部分。

## 目标

- 每期周刊发布后，Agent 能从 `src/content/blog/weekly-N.md` 出一支约 8 分钟、可以直接上传 B 站的 1920×1080 成片，同时给出 B 站发布用的配套材料。
- 画面不能平淡：屏幕上一直有东西在变化，不允许一张图静止停留几十秒。
- 讲到原文时，画面像在浏览器里打开那篇文章，滚动到重点段落，再用荧光笔把重点句标出来。
- 制作流程沉淀成仓库里的 skill 和脚本，下一期照着跑就行。

## 非目标

- 不覆盖周刊全部条目。
- 不做数字人，也不需要山月出镜。
- 不自动上传 B 站。Agent 只产出文件，由山月自己上传（我的决定）。
- 不另做竖屏短视频切条（我的决定，以后可以作为新需求再提）。

## 反目标（技术上做出来了也算失败）

- 一张静态图挂很久，或者通篇是「截图 + 念稿」。
- 口播稿是书面语直接朗读，听起来像念公文。
- 出现周刊里没有的事实、数字，或者把数字讲错。
- 每期需要山月花大量时间修，或者每期都得重新设计一遍流程。

## 已确定的决定

### 结构与时长（山月定）

| 段落 | 时长 | 内容 |
|---|---|---|
| 开场 | 约 15 秒 | 期号和本期一句话主题，直接进卷首，不做长片头 |
| 卷首 | 约 2 分钟 | 约 550 字。讲论点、关键数字和落地判断，保留意见压成一两句 |
| 快讯速览 | 约 1 分钟 | 4–5 条，每条一句话加一个画面 |
| 精选文章和工具 | 约 4.5 分钟 | 大约 7 条，每条 35–40 秒，讲「发生了什么 + 落地建议」 |
| 结尾 | 约 20 秒 | 其余内容去 Web 版看，链接放在简介里 |

全片约 8 分钟。中文口播按每分钟 260–280 字估算，全片口播稿约 2100 字。

### 选题（山月交给 Agent）

快讯、文章和工具由 Agent 挑选。优先挑以下几类条目：

1. 有可视化的数字对比。
2. 有能演示的东西，比如一个 API 返回值，或者一个操作流程。
3. 有能用分步动画讲清楚的机制。

纯消息类的条目放进快讯速览。如果某条和卷首主题高度相关，可以从卷首挪出来，在精选里单独讲（例如 #62 的「把判断交给决策模型省 29.6%」）。

### 视觉风格（山月定：方案 B，纸面编辑风）

- 米色纸底 `#f5efe3`，标题用宋体（Songti SC），正文和字幕用苹方（PingFang SC），正文色 `#2b2622`。
- 强调色是朱红 `#b23a2e`，荧光笔是黄色 `#ffd84d`。批注框有轻微倾斜，像手写批注。
- 左上角放来源标签（期号 · 栏目，或者原文域名）。底部烧录字幕。
- 样稿在 `.superpowers/brainstorm/48438-1792398977/content/visual-style.html` 的 B 行，不进 git。

画面素材分三类，按这个顺序优先使用：

1. **原文网页加荧光笔**（山月特别要求）。画面像在浏览器里打开原文：页面平滑滚动到重点段落，荧光笔手绘式划过重点句，可以划线、圈数字、加框。英文原文划英文原句，旁边用中文小批注写出关键信息。
2. **自制动画**：数字对比做成柱状图生长或者数字跳动，流程和机制做成分步出现的示意图。
3. **现有配图加镜头运动**：周刊里 `src/assets/blog/weekly-N/` 的配图不静放，要用推近、局部放大、逐块点亮。

节奏底线：任何一个画面静止不超过约 6 秒。超过就要有新的动作，比如滚动、划线、切镜或批注。

### 声音（山月定：AI 克隆声音）

- 沿用 `/Users/wangx/code/projects/ai-interview-series` 的做法：本机 Qwen3-TTS（mlx-audio）的 Base 模型，克隆山月的参考音。参考音是 `av/ref/interviewer.wav`，`ref_text` 写在该仓库的 `av/voices.yaml`。不走云端，也不需要 API key，只能在 Apple Silicon 上跑。
- 逐句合成，按「文本 + 音色 + 参数」做缓存，改一句只重合成那一句。
- 用本机 Whisper（mlx-whisper）出字级时间戳，用来生成字幕，也用来让画面动作对准口播：念到某个数字，数字正好出现；念到某句，荧光笔正好划到那句。
- **试听不过关时的备选（山月定）**：如果克隆声音念长段落发僵或者音色不稳，先从山月的其他 B 站视频里重新截一段更合适的参考音（10–15 秒、单人、无背景音乐，最好是平稳讲解的语气），再重合成试听。可以用 ai-interview-series 的 `python -m av ref <BV号> --start --end` 截取和转写，`ref_text` 要逐字核对。候选片段由 Agent 从频道 https://space.bilibili.com/28696526/ 里找，交给山月确认。
- 不使用 HyperFrames `media-use` 自带的 HeyGen 云端声音克隆（我的决定，原因是要和现有本机方案保持一致，并且不依赖外部账号）。

### 制作框架（山月定：HyperFrames）

- 用 HyperFrames 把 HTML 渲染成视频。HyperFrames 的核心 skills 已经装到全局（`~/.agents/skills/` 等目录）：`hyperframes`、`hyperframes-core`、`hyperframes-animation`、`hyperframes-keyframes`、`hyperframes-creative`、`hyperframes-cli`、`hyperframes-registry`、`hyperframes-studio`、`hyperframes-audio`、`media-use`。
- 8 分钟超过专项流程大约 3 分钟的上限，所以按 `/hyperframes` 的路由走 `/general-video`。用之前先运行 `npx hyperframes skills update general-video` 安装。
- 每期在项目根目录写一份 `BRIEF.md`，内容取自本文档：`workflow: general-video`、`flow: automation`、`storyboard: no`（山月不看分镜，只看成片）、`aspect: 16:9`、`language: zh`。这样 HyperFrames 不会再走一遍意图访谈。
- 视觉规范写成 HyperFrames 的 `frame.md`，所有期共用。

### 审核方式（山月定）

Agent 自己完成选题、口播稿、素材、合成和渲染。山月只看成片，提出修改意见，再由 Agent 修改。

- **先渲染，后审核**：Agent 直接渲染出 `program.mp4` 交给山月看，不在渲染前停下来等确认。HyperFrames 的工作流默认在渲染前打开 Studio 询问「现在渲染还是先改」，这一步要在 skill 里明确跳过（我的决定，依据是山月说「我就看看最后的成品效果，然后让你改正」）。Studio 预览可以顺手打开，但不阻塞。
- **修改由 Agent 执行**：山月用文字提意见，Agent 改源数据后重新生成。合成 HTML 由口播稿、时间戳和抓取坐标等数据生成，每次都会覆盖重写；山月在 Studio 里手动改的内容不会保留（我的决定）。

## 每期产出

- `program.mp4`：1920×1080，带烧录字幕和音频。
- `captions.srt`：可以作为 B 站 CC 字幕上传。
- B 站发布材料（一个 Markdown 文件）：
  - 标题：五条候选，用户选一条。每条 ≤80 字，都带期号；选定前不写死。
  - 分区、标签：随标题一起给出。分区在「科技 · 计算机技术」「科技 · 软件应用」「知识 · 科学科普」里选一档。
  - 简介：卷首和精选的短介绍，加上本期来源链接，以及 Web 版链接 `https://weekly.shanyue.tech/weekly-N/`。
  - 章节时间点：按段落切分，用于 B 站进度条分段。
  - 封面：按 B 风格单独排版。封面文案和投稿标题分开写。

## 触发方式

每期周刊发布后，山月在 Agent 会话里手动说一句「做第 N 期视频」，触发 skill（我的决定）。TTS、对齐和渲染都在本机跑，耗时较长，所以每个阶段的产物都要落盘、带缓存：选题、口播稿、逐句音频、时间戳、网页抓取、合成、成片。中途断了，下次从上次停下的阶段继续，不从头跑。

## 约束

- 只在山月的 Mac（Apple Silicon）上跑，Node ≥ 22.12，本机已有 ffmpeg。
- 渲染必须确定性：合成里不能在渲染时联网、不能用 `Date.now()`、不能用不带种子的随机数（HyperFrames 规则）。所以原文网页要在渲染前离线抓好。
- 克隆参考音和本机模型文件不进 git。
- 周刊仓库是 pnpm 工作区（`pnpm-workspace.yaml`），视频工程不能影响 `pnpm build` 和 Vercel 部署。
- 不擅自 `git commit` 或 `git push`。

## 留给实现者决定的部分

- **原文网页素材怎么做（我的倾向）**：渲染前用无头浏览器打开原文，以 1920 宽截取整页长图，同时记录重点句在页面上的坐标。合成里用位移模拟滚动，用 SVG 在这些坐标上画荧光笔。这样做是确定性的，荧光笔也能精确对准口播时间。可以参考 `npx hyperframes capture`，但它是为整站抓取设计的，不一定合用。打不开或者反爬的站点（需要登录、弹窗多，比如 X、Medium），退回到截图加高亮，不能卡住流程。
- 工程放在仓库的哪个位置、怎么和 Astro 站点隔离，脚本用什么语言。
- 克隆 TTS 是直接调用 ai-interview-series 的环境，还是在周刊仓库里放一个小脚本，复用同一个模型和同一段参考音。
- 背景音乐：第一期默认不加（我的决定），后面可以再试。
- 片头片尾的具体样式、转场方式、批注字体细节，要在 B 风格内保持统一。
- 把以上流程写成仓库里的 skill，比如 `.agents/skills/weekly-video/`，并在 `AGENTS.md` 的「每周流程」里补一步。
