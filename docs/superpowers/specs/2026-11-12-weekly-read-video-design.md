# 单篇精读视频（B 站）设计

日期：2026-11-12
状态：待确认（已过审阅者通读）

## 意图

每期周刊视频做完后，再从当期周刊的「技术文章」里挑五篇，每篇单独做一支 3–5 分钟的 B 站视频。五支一次做完，用 B 站的「定时发布」排成每天一支。

周刊视频七八分钟要讲十几条，每篇只能点到一两句。单篇视频给一篇文章三到五分钟，可以把它讲完整：讲清楚这篇在解决什么问题、怎么做的、有哪些数字、有哪些局限。观众看完不用自己读英文原文，也能知道这篇讲了什么。

画面以周刊里「浏览器打开原文、滚动、荧光笔划线」的效果为主，但改成全屏。因为整支视频只讲一篇，划线的句子可以多得多。英文原句划线后，在原句下方展开对应的中文译文。

## 目标

- 从一期周刊出五支单篇视频：每支 1920×1080 成片 + 四张主封面 + 五张矩阵封面 + B 站投稿文案，并在 B 站设好定时发布（每天一支）。
- 画面是全屏的原文网页：左、右、上都没有纸面留白；页面推近到正文栏，让文字占满宽度。
- 每支划线约 12–20 句，每句英文原句都配中文译文。
- 制作流程写成 skill（`.agents/skills/weekly-read/SKILL.md`），下周照着跑。

## 非目标

- 不改周刊视频的样子。新效果（手绘荧光笔等）先只用在单篇视频，周刊要不要跟进以后再说。
- 不选工具推荐里的条目，只选技术文章。
- 不做竖屏切条。
- 不用红笔圈数字（讨论过，山月没选）。

## 反目标（做出来了也算失败）

- 口播在念译文。口播是转述和解释，译文是原文的意思，两者不重复。
- 译文或口播里出现原文没有的事实或数字，或者把数字讲错。
- 推近后文字发糊，或长图拼接处有接缝。
- 一支视频静止超过约 6 秒（沿用周刊规范）。
- 周刊视频因为这次改动，输出有任何变化。

## 已确定的决定（山月定）

- **第一批**：#66。先做一支样片（「Agent 记忆的组成：当场记录与睡后整理」），山月看过再做另外四支，五支都真的上传。
- **节奏**：周刊视频做完后，一次做完五支，一次上传完，用 B 站「定时发布」排成每天一支。
- **选文**：只从当期周刊的「技术文章」里选，不选工具。
- **口播与译文的关系**：口播不念译文，只转述和解释。译文和底部字幕同时在屏可以接受，因为观众不一定看字幕。
- **译文效果**：原句下方展开。划线后，页面从这句下面裂开一道缝，下半部分往下滑，中文译文逐字写进去，像沉浸式翻译插件的双语对照。讲下一句前缝合上。
- **其他效果**：手绘荧光笔、聚光（当前段落以外变暗）、数字大字卡、原文配图放大。
- **实现方式**：另写 `video/scripts/build-read.mjs`，不在 `build.mjs` 里加格式；字幕时间、声音后期等公共代码先抽成共用模块，两个生成器都引用（见「实现方式」）。

## 实现方式

讨论过的三种：

| 方案 | 做法 | 取舍 |
|---|---|---|
| A | `build.mjs` 加 `format: "read"` 和一种 `read` 场景 | 改动最小，但周刊和单篇挤在一个文件里，改单篇就有改坏周刊的风险 |
| **B（选定）** | 另写 `build-read.mjs`，公共代码抽到 `scripts/lib/` | 周刊生成器的逻辑不动；抽公共模块时要动一次 `build.mjs`，用「输出完全一致」来验收 |
| C | 单独建一个 npm 包 | 重复代码最多，不选 |

### 抽公共模块

从 `build.mjs` 抽到 `video/scripts/lib/`（文件怎么分由实现者定），至少包括：

- 口播时间：`clauses`、`mapIndex`、`loadScene`（含 `cue`）、`captionsFor`。
- 声音：`VOICE_CHAIN`、`masterVoice`、`silence`、整条口播的拼接与时长核对。
- 工程组装：`subDoc`、`index.html`、`captions.html`、工程脚手架文件、SRT、`timeline.json`。
- 版面参数（字幕位置、字号等）作为参数传入，不要写死在共用模块里。

从 `publish.mjs` 抽出封面相关的公共部分（`doc`、`browser`、`evidence`、截图）给 `publish-read.mjs` 用。

**验收**：抽完后对 `episodes/weekly-64` 重跑 `build.mjs` 和 `publish.mjs`，`index.html`、`compositions/*`、`out/captions.srt`、`out/bilibili.md`、`assets/vo.wav` 与抽之前逐字节一致（封面 PNG 可以只对比像素）。

### 抓取（`capture.mjs`，在原文件上加功能，默认行为不变）

- **只对单篇生效**：下面的新行为只在 `episode.json` 是 `format: "read"` 时打开。周刊的抓取保持现状：1.5 倍、单张图、`MAX_HEIGHT` 9000 CSS px 截断、截到最低高亮下方 900 px。周刊的 `build.mjs` 和 `publish.mjs` 只认单张 `cap.image`，不改（我的决定：现有周刊抓图已有 13500 设备像素高的单张图，若对周刊也切片，周刊生成器就得改）。
- **清晰度**：单篇要推近到正文栏，正文栏常见 650–760 px 宽，铺满 1920 需要约 2.6 倍，所以单篇用 3 倍清晰度抓。清晰度从 `episode.json` 的 `capture.dpr` 读。
- **整篇抓取**：单篇不截断，抓到正文结束。
- **切片**：3 倍清晰度下长文可能三四万像素高，超过浏览器单张图片的上限，所以长图按高度切成若干张（每张不超过 8192 设备像素），抓取 JSON 里用 `images: [{file, y, h}]` 记录，`build-read.mjs` 和 `publish-read.mjs` 拼回去，拼接处不能有缝。
- **正文栏**：记录正文栏的矩形（`article`、`main` 或包住所有高亮的最小块），生成器据此计算推近倍数。
- **段落**：每处高亮额外记录它所在段落（最近的 `p` / `li` / `blockquote` / `h*`）的矩形，聚光用它。
- **配图**：`pages.<id>.figures: [{id, match}]`，`match` 是图片 `src` 或 `alt` 里的一段字符串；抓取记录图片矩形，找不到时报错，和找不到高亮的处理一致。

### 生成器（`build-read.mjs`）

**版面**

```
┌────────────────────────────────────────────────────┐
│ ● ● ●  [图标] 文章标题                claude.com/… │ Chrome 栏，贴住顶边
│                                                    │
│   …原文正文（推近到正文栏，占满宽度）…              │
│   ▇▇ The final setup's reviews are more precise ▇▇ │ 手绘荧光笔
│   ┆ 最终方案的评审比基线更准（46.8% 对 41.9%）      │ 译文（页面在此裂开）
│   …原文继续（下半部分下滑）…          ┌─────────┐  │
│                                       │ 红色批注 │  │
│                                       └─────────┘  │
│▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁ 口播字幕（压在页面上）▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁│
└────────────────────────────────────────────────────┘
```

- 浏览器窗口铺满 1920×1080，复用 `chrome.mjs` 的 Chrome 栏，不要圆角和阴影。没有纸底、页边线和章节进度。
- 推近倍数 = 1920 ÷（正文栏宽 + 两侧各约 60 px 余量），上限是抓取清晰度（3），保证不糊。
- 字幕沿用周刊的位置和字号，压在页面上，底色用卡片纸色，半透明程度由实现者定，以压在白底文字上仍然可读为准。

**一句划线的过程**（一个 `beat`，时间点用 `at` 卡口播原词，和周刊一样）

1. 页面滚到这句，放在画面约 40% 高处（0.9 秒，`power3.inOut`）。
2. 聚光：这句所在段落以外的部分变暗（约 0.4 秒）。
3. 手绘荧光笔逐行从左往右扫过原句。笔迹是 SVG：边缘不规则、两端不齐、每行有不到 1° 的随机倾斜。随机数用高亮 id 做种子，保证每次渲染一样。颜色仍是 `#ffd84d`，正片叠底。
4. 页面在这句最后一行下方裂开，下半部分往下滑，滑出的高度等于译文块高度（约 0.5 秒）。译文逐字写入，写完时长不超过约 1.2 秒。
5. 停住，口播解释。停留期间沿用周刊的极慢推近，避免画面静止。
6. 下一处划线开始前，缝合上，聚光恢复，再滚过去。上一处的荧光笔保留，但变淡（同周刊）。

译文块：苹方，字号接近推近后原文正文的视觉大小，墨色，左侧一条 4 px 朱红竖线，底色用卡片纸色，宽度等于原句所在段落宽。

**数字大字卡**：`beat.stat: {value, label}`。页面整体压暗，宋体朱红大字的数字加一行说明从中间弹出，停约 2.5 秒（或停到 `until` 指定的口播原词），再退回页面。数字必须出现在当时已经划线的那句原文里。每支最多两次。

**配图放大**：`beat.figure: <figure id>`。页面推近到让这张图在字幕上方完整铺满，停到下一个 beat。推近倍数不超过抓取清晰度。每支最多三次。

**红色批注**：`beat.note`，写山月的判断，不写翻译。浮在页面右侧，竖直方向放在远离当前划线的那半屏；挡住的是被聚光压暗的段落，可以接受。样式沿用周刊的批注框。

**开头和结尾**：开头不做片头，第一屏是页面顶部（文章标题），第一句口播说这是周刊第几期的精读、这篇讲什么、为什么值得看。结尾最后一屏在页面上叠一张小卡：周刊网址 + 「完整周刊 #N」。

**时长**：总长不在 150–330 秒内时，build 打印警告，不报错。

### `episode.json`（单篇）

在周刊 `episode.json` 结构上的改动：

- 顶层：`format: "read"`、`issue`、`slug`、`title`（文章中文标题，取自周刊里的卡片标题）、`day`（1–5，第几天发）、`capture: { dpr: 3 }`、`pages`（通常只有一个）。
- `pages.<id>.highlights[]` 多一个 `zh`（译文）；新增 `figures`。
- 场景只有一种类型 `read`；一篇文章按原文小节拆成几个场景，共用同一张长图。`chapter` 是小节名，用于 B 站简介时间轴。
- `beats[]`：`at`、`highlight`、`note`、`stat`、`figure`。
- `bilibili`：`cover`、`matrix`、`tags`、`intro`、`publishAt`。

`tts.py` 只读 `scenes[].lines`，不需要改。

### 发布（`publish-read.mjs`）

- **标题**：`开发者 AI 周刊 #N 精读｜<文章中文标题>`，不超过 80 字。
- **封面**：四张主封面沿用周刊版式，kicker 改成「开发者 AI 周刊 · #N · 精读」。矩阵封面五张，用同一篇里五处不同的划线（B 站最多收五张）。
- **简介**：两三句概要 + 时间轴（按 `chapter`）+ 原文链接 + 周刊链接。
- **标签**：6–10 个，必须包含 `开发者AI周刊` 和 `AI精读`。
- **合集**：五支都加进 B 站合集「开发者 AI 周刊 · 精读」（账号有合集权限，山月确认；合集不存在时，第一次上传时创建）。
- **定时**：`bilibili.publishAt`（`YYYY-MM-DD HH:mm`，北京时间）由 Agent 写进每支的 `episode.json`：默认第一支是上传日次日 12:00，之后每支加一天（我的决定，山月可以改）。没有文件记录周刊视频的发布日，所以不从它推算。`publish-read.mjs` 把它写进 `out/bilibili.md`，并检查它在「现在 + 2 小时」到「现在 + 15 天」之内，否则报错。

## Skill（`weekly-read`）

触发：「做第 N 期精读」「单篇视频」「精读视频」。内容按 `weekly-video` 的结构写，重点：

1. **选文**：读 `src/content/blog/weekly-N.md` 的「技术文章」，选五篇。条件：原文篇幅够讲 3 分钟以上（约 1500 英文词以上）、有可核对的数字或能画的机制、网页能抓。列出五篇和理由，**等山月确认后**再写口播。每批先做一支样片，山月看过再做其余四支（第一批必须这样，样片版式定稿后可以省略）（我的决定：口播和 TTS 成本高，选错再换比先问一句贵）。
2. **抓取**：`--dump` 导出正文，逐字复制要划线的原句，写译文 `zh`；再正式抓取，必须全部 `found`。
3. **口播**：按原文顺序带读，每支约 50–70 句（每句 ≤ 40 字），去 AI 味规则沿用 `dev-ai-weekly` §4.7.1。第一句报「开发者 AI 周刊第 N 期精读」+ 文章是什么；结尾落到落地判断，第 1–4 支以「我是山月，我们明天见」收尾，第 5 支以「我是山月，我们下期周刊见」收尾（我的决定）。
4. **译文**：忠实原文，术语和产品名保留英文，不加原文没有的信息。
5. **对齐规则**：沿用周刊——口播里的数字和事实必须出现在念这句时正亮着的那句原文里。
6. **多音字**：沿用 `voice.json` 的 `polyphones` 流程。
7. **合成 → 生成 → 检查 → 渲染 → 发布材料**：命令和周刊对应，检查时对每个 beat 截图，看译文是否压字、裂缝位置是否对、拼接处有没有缝。
8. **B 站上传**：沿用周刊的 ego-browser 步骤，另加：选合集、打开「定时发布」并设好 `publishAt`。五支依次传完，每支停在填好的页面，由山月点投稿（山月明确说让 Agent 点时才点）。

同时更新：`AGENTS.md` 每周流程第 5 步后加一步「（可选）精读视频」；`weekly-video` skill 末尾指向 `weekly-read`；`video/frame.md` 加一节单篇视频的版面与动效。
