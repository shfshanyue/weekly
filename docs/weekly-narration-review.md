# 配音前完整口播审核

适用于周刊视频和单篇精读。口播稿完成后、整支 TTS 合成前，每次都从头到尾按以下顺序审三轮；正文已审不能替代口播审核。直接执行此流程，不设样片试跑或用户逐句确认环节。

1. **文风**：读 `../.agents/skills/dev-ai-weekly/SKILL.md` §4.7.1，逐句检查完整口播。把空话、口号、强行类比、模板建议改成具体事实、机制或这条独有的动作；书面长句拆成一句一个信息的口语短句。连起来通读，检查生硬转场和重复总括。重点靠改句子解决，不靠扩充禁用词表。
2. **语义**：读 [术语表](weekly-terminology.md)，把口播、字幕原文及画面译文与原文核对，检查术语、数字、因果和限制条件。新参数、歧义词回查官方定义；无法确认就保留英文并说明不确定之处。文风修改过的句子重新核对语义。
3. **读音**：检查多音字、英文、数字与单位。用 `voice.json` 的 `polyphones` 或逐句 `say` 纠音，字幕保持正确原文；含义错误先改正式稿，不靠读音替换遮盖。可疑句先单独合成验证，读错就修正后重测；没有实际试听或音素检查，不得记录成已验证。

## 完成条件与记录

每支视频在工程目录 `.work/narration-review.md` 分别记录三轮的审核范围、问题句（场景 / 句子标识）、修改前后、核对依据或试音结果，以及通过 / 待处理状态；无问题也记录覆盖范围与结论，不只写一句“已审”。这是本地审核记录，不改变各工程的 git 跟踪规则。

三轮均完成、发现的问题已处理后，才开始整支配音。改稿后重查受影响句子的三项；已合成的内容只重合成受影响句子。此流程不自动修改、重渲或重新发布历史视频。
